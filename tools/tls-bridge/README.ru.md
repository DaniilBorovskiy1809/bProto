# TLS-мост bProto

Схема: клиент bProto → локальный UDP → TLS 1.3 → серверный мост → сервер bProto.
Формат bProto внутри TLS не меняется. Серверный мост запускается командой
`python3 tools/tls-bridge/bridge.py server tls-server.json`.
Конфигурация экспортируется из Settings панели.

## Android

На Android 10+ можно экспортировать TLS-ключ: укажите в панели существующий ключ
bProto, домен сертификата, адрес сервера, TCP-порт и общий токен моста.
Скачанный текст импортируется в приложение как обычный bproto://import/ ключ.
TCP-сокет защищается через VpnService.protect до подключения; проверка имени
сертификата обязательна. Используется системное хранилище CA. Самоподписанный
сертификат без доверенного CA не принимается. Старый UDP-режим сохраняется.

Поле `tls` внутри JSON ключа содержит `hostname`, `server_host`,
`server_port`, `token`. Ключ содержит секреты; не публикуйте его.
Профили приложения сохраняются существующим зашифрованным ProfileStore.
При разрыве TLS мост останавливает native-туннель; бесшовного восстановления нет.
На Android 8/9 TLS-режим отклоняется, вместо молчаливого перехода на UDP.

## Проверки

Python: `python3 -m unittest discover -s tests -p test_tls_bridge.py -v`.
Android: `gradle -p apps/android testDebugUnitTest assembleDebug`.
Сборка и unit-тесты не заменяют проверку VpnService на устройстве.
Реальный Android e2e пока не подтверждён.

## Ограничения

QUIC/HTTP3, ECH, браузерные отпечатки, CDN-fronting и агент применения пока
отсутствуют. Экспорт настроек не выполняет развёртывание. HTML fallback — локальная
страница оператора, а не подмена чужой TLS-сессии. 100% гарантии обхода РКН нет.
Реальная проверка белого списка требует разрешённого узла под контролем оператора.

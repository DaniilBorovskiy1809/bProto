# Экспериментальный QUIC / HTTP3-мост

Схема: bProto UDP → локальный мост → HTTP/3 DATA в QUIC v1 → серверный мост → bProto UDP.
Формат bProto и его ключи не меняются. Используется aioquic, настоящий TLS 1.3,
ALPN h3, HTTP/3 и обязательный Retry на сервере. Это отдельный Python-модуль;
Android QUIC пока не интегрирован.

## Настройка

Установите зависимости из requirements.txt в venv. Скопируйте server.example.json
и client.example.json за пределы репозитория. Укажите свой домен, сертификат,
порты и upstream существующего bProto-сервера. Сервер по умолчанию слушает loopback.
Для удалённого доступа явно измените listen_host. В обеих средах задайте одинаковый
BPROTO_BRIDGE_TOKEN: случайный секрет из 64 шестнадцатеричных символов.
Значение хранится в окружении, не в JSON и не в Git.

Запуск: `python bridge.py server /etc/bproto/quic-server.json` и
`python bridge.py client /etc/bproto/quic-client.json`.
Клиент bProto подключается к 127.0.0.1:14443 со своими прежними ключами.
Перед включением полного туннеля закрепите отдельный маршрут к внешнему QUIC-серверу:
native-клиент видит только loopback. Опциональное поле ca клиента позволяет
использовать тестовый CA без отключения проверки имени сертификата.
Изменения конфигурации применяются перезапуском без пересборки.

Неавторизованный HTTP/3-запрос получает локальную HTML-страницу владельца сервера.
Это не подмена чужой TLS-сессии и не заимствование чужого сертификата.

## Проверки и ограничения

Семь тестов проходят; покрытие строк модуля — 80%. Проверены Retry, QUIC v1,
UDP-обмен, локальный клиентский мост, GET fallback, неверный токен, неверное имя
сертификата и фрагментация кадров. Команды тестирования приведены в README.md.

Независимая проверка curl/Wireshark, Android e2e, Интернет через TUN и реальный DPI
не выполнены. Нужны нагрузочные проверки ограничений очередей перед публичным
развёртыванием. Нет Android QUIC, ECH, браузерных отпечатков, CDN-fronting,
автопереподключения и агента применения. 100% гарантии обхода РКН нет:
необходим доступный разрешённый узел под вашим контролем.


## Native Rust / Android HTTP3

Вместо заглушки vpn-core теперь работает HTTP/3-клиент на h3/quinn.
Android сначала создаёт внешний UDP-сокет, затем вызывает protect(fd), и только
после этого начинает handshake. JNI управляет runtime; закрытие отменяет задачи.
В панели появился выбор QUIC / HTTP3 и экспорт Android-ключа.

Поле quic содержит hostname, server_host, server_port, token; оно несовместимо
с одновременным tls/wss. Python-сервер получает общий токен через окружение.
Apply панели пока относится к raw-TLS: QUIC JSON развёртывается отдельно.

Проверка имени сертификата обязательна. Android QUIC использует встроенные
Mozilla/WebPKI roots, а не пользовательские CA Android. Частный DER CA доступен
для native Rust API и тестового CLI, но не через импорт Android.

Тесты Rust↔aioquic проверяют обмен, неверный токен/имя, native handshake bProto и
выдачу адреса. Также исправлено освобождение upstream UDP при остановке сервера.
Сборка трёх ABI и JVM-тесты не заменяют VpnService e2e на устройстве. ECH,
браузерные отпечатки и гарантированный обход РКН отсутствуют.
